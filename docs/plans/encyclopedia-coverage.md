# Encyclopedia coverage inventory

This is the working checklist for the player Adventure Guide. “Exported” means the field is sourced and searchable or shown in the Guide; “partial” means a sourced subset is present; “open” means it needs extraction, source review, or authored explanation. Raw code and config values must not be presented as player-facing effect prose.

The [completion plan](encyclopedia-roadmap.md) sets the work order, evidence states, and release gates. This inventory supplies its field-level backlog; generated [coverage counts](../encyclopedia-coverage.v1.json) track exported dimensions against denominators for the current source revision.

## What a useful reference entry should answer

- **Identity and provenance:** stable ID, player name, aliases, source file/record, source revision, and whether the data is server-specific or estimated.
- **How it works:** observable effect, costs, conditions, duration, limits, failure cases, and any uncertainty. A raw script or internal flag is not an explanation.
- **How to get/use it:** prerequisites, requirements, prices, drops/rates, crafting/combination, NPC/service, location, and route when known.
- **What connects to it:** incoming/outgoing links to monsters, items, cards, skills, statuses, jobs, maps, NPCs, quests, and mechanics.
- **Coverage label:** distinguish “none found in loaded source” from “not searched,” conditional behavior, and missing or unverified data.

## Collection order

1. **Low-risk structured facts:** item restrictions, item groups, and literal loaded-script shop stock are now exposed. Source-linked membership for 436 combos links 748 items; 57 random item groups provide 4,227 weighted container/outcome links; 1,854 shop offers across 235 NPC declarations link 366 items to maps, coordinates, prices, and source lines. Next: trace cash/barter/runtime shops and crafting; index literal quest targets/rewards.
2. **Location and acquisition:** NPC/service coordinates and conditions; monster conditional spawn sources; crafting and item-group sources; map flags and entry routes.
3. **Reviewed explanations:** expand beyond the conservative item script allowlist to cover conditional item/card effects, skill/status effects, formulas, quest branches/rewards, boss behavior, and DM/session rules. Each explanation needs a code/data citation and an explicit uncertainty label.
4. **Acceptance and drift:** regenerate deterministically, validate source revision and links, compare a sample against the running server, and inspect presentation in the player Guide.

## Evidence rule

A script/API call is a lead, not proof of its player-facing role. A configured amount is not a live count; a configured base rate is not always the final outcome. Keep raw values available as provenance, but expose prose only when its source and conditions have been checked. Unavailable, unsearched, conditional, and verified-empty are distinct states.
