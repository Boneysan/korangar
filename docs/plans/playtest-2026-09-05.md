# Playtest feedback — 2026-09-05, first session with friends

Four players, three remote over Tailscale. Everything below came from that
evening. Status is what I verified in code, not what I assume.

## Fixed

| Item | What it was |
|---|---|
| **Quest window never appears** | `Ctrl+Q` was bound **twice** — `ToggleQuestLogWindow` and `CloseTopWindow` fired in the same frame, so the log opened and immediately closed. It shipped 2026-08-25 and had never once been visible. Close moved to `Ctrl+W`. Not DM-only. |
| **Windows client white / no graphics** | Nothing chose the graphics backend: `adapter_score` scored only `device_type`, so the Vulkan and DX12 entries for one card tied and `max_by_key` let *enumeration order* decide. AMD now prefers Vulkan. **Needs a pack rebuild to reach anyone.** |

## Answered — these exist

- **`Alt+U` is not bound to anything.** Party is **Alt+Z** / **Alt+P**; quest log
  **Ctrl+Q**; inventory Alt+E; equipment Alt+Q; stats Alt+A; skills Alt+S;
  zeny/EXP HUD Alt+Shift+H; minimap Ctrl+Tab.
- **Auto-pickup exists**: `@autoloot <percent>`, and a button in the Commands
  window (Ctrl+O). The number is a **drop-rate threshold** — `@autoloot 1` takes
  only rare drops and leaves junk. Requires GM, so run it on a friend with
  `#autoloot "Char Name" 100`.
- **Client-only updates already work** — that is why the pack is split.
  `Seal-Cascade-Windows.zip` is 47 MB against 4 GB. **Not written down anywhere a
  friend can read**, which is the actual gap.

## Confirmed missing (feature requests, not bugs)

- Items/potions in the hotbar — skills only, no item support in the hotbar code.
- Multiple hotbar pages (Alt/Ctrl tiers) — one row, F1–F9, nine slots.
- WASD movement — `W`/`A`/`S` exist only for the debug camera and modifier chords.
- Names when hovering the minimap — blips only, no hit-testing.
- Teleport-to-party-member from the party window — `@jumpto` works but is GM-only.

## Bugs still to chase

**Head detaches on character select at facings 9 / 12 / 3.** Character select
draws characters as **world entities**, so this is the general attachment path
rather than a UI preview — and it may therefore affect the world too. **Do not
theorise about the offset.** Head placement has been guessed wrong five times on
this project; the only thing that has ever worked is printing the whole
computation per facing and letting the data name it. The creation preview
deliberately submits **one composed animation** so normal attachment rules hold
for all eight facings — compare against that first.

**Party window keeps showing the old job.** Wiring looks intact end to end:
Hercules calls `pc->update_job_and_level` from `pc_jobchange` (`pc.c:9019`), the
client registers `0x0ABD`, and its handler updates `job_id` **and** `class_name`.
So something subtler is wrong — watch the packet live rather than guess.

**Stat allocation may not apply.** BigZ reached base 3 with **54 unspent points
and every stat at 1**. Either the allocator was skipped at creation, or the
2026-09-04 replay fix does not fire. Needs one controlled character creation
with the allocator definitely used.

**`iz_ac01`: warps to a black screen, plus invisible walls.** Precedent exists —
`docs/MAP_TELEPORT_AUDIT.md` came from campaign teleports with bad coordinates.
Needs the specific warp coordinates from the player.

**Character creation text is too small on a 15" laptop.** Interface scale, not a
layout bug. Check whether the interface settings expose a usable scale.

**Headgear animation audit** — check every headgear renders and animates. A
systematic pass, not a quick check.
