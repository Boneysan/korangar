## Build and provenance

`tools/export_supported_data.py` is the reproducible entry point for the currently supported exporters; it runs them in a fixed order and supports a non-mutating `--check`. Restored parallel outputs are `docs/items.v1.json`, `docs/cards.v1.json`, and `docs/bestiary.v1.json`, preserving the legacy JSON consumed by the DM tools. These v1 files record schema version, source revision/dirty state, renewal mode, and source path/record for each entry and drop link. A conservative allowlist summarizes supported item/card script patterns, including selected literal conditional branches; unsupported patterns remain untranslated, and the export does not infer stacking or cross-effect interactions. Bestiary v1 covers DB stats, modes, mob skills, normal/MVP base drop rates, and 3,380 loaded static spawn directives across 965 of 1,759 monsters, plus 1,217 resolved direct script-spawn call sites across 420 monsters. Sixty calls have literal map and coordinate data, and 376 more are approximately associated with an instance template using nearby script assignments; those templates are searchable in the Guide. Remaining dynamic map expressions remain unassigned. Call triggers, exact runtime populations, and randomized cells are not inferred, and configured counts are not live population counts. The legacy `docs/items.json`, `docs/cards.json`, and `docs/bestiary.json` are not regenerated; do not claim full G1 completion. Packaged client data must match the server revision; a mismatched pack displays its data revision and treats rate/rule values as possibly stale.

`tools/export_skill_info.py` and `tools/extend_bestiary_export.py` are starting points. The original exporter for the current `bestiary.json`, `items.json`, and `cards.json` was not committed. `tools/export_item_reference.py` and `tools/export_bestiary_reference.py` now generate versioned parallel files and reject duplicate IDs/names, parse failures, and dangling drop links. Restore deterministic generation for the legacy bestiary/items/cards files (or migrate consumers) before calling those legacy artifacts generated. Report category counts and coverage. Authored text/overrides live in a separate reviewed file with an explicit source and may be localized later.

## Client model and knowledge policy

Use stable `category:id` keys, normalized search aliases, display name, concise summary, source/provenance, and typed links. Search returns all matching entries with category labels; cross-links use IDs, not string matching. Unknown or unsupported fields are omitted or marked “not documented yet”; never silently show a default that may be false. A partial category may ship if its coverage is plainly labeled.

**Open Database is the friends-server baseline.** Every generated reference entry and verified build-relevant field is searchable from a fresh account: monster stats, element/race/size, skills and weaknesses, item/card effects and sources, drop rates, skill costs/prerequisites, jobs, maps, mechanics, and effective server rules. Search indexes names, aliases, effect terms, source monsters, and cross-linked IDs, with category filters. Unsupported or unverified fields say “not documented yet” rather than appearing locked. Campaign plot spoilers and DM-only actions are separate from mechanics. Account-wide discovery is a progress/history layer, never a prerequisite for reference information. A more restrictive knowledge mode would be a later explicit server-owner decision; it is not a dependency of this plan. The DM Bestiary's session-only kill list is not the authority for player discovery. No peer party message can grant an unlock.

The player window currently offers an All search plus category filters for monsters, items, cards, skills, verified graph map identifiers, 151 exported job names, status icon names, and a static quest catalogue merged with active server quest entries. Item/card search matches exact numeric IDs, names, Aegis aliases, raw exported effect tags, and verified drop-source monster names/aliases; it matches translated natural-language effects when available and retains raw effect tags; scripts outside the supported patterns remain marked untranslated. Monster details list up to eight exported `mob_skill_db.conf` entries with their raw rate/delay values, link matched skill constants to versioned skill records, and retain raw names when no skill record matches. `quests.v1.json` contains tracked Hercules quest names and explicit hunt targets; 842 quests also have related, statically-located NPC-script references extracted from `npc/re/quests` and `npc/custom`. `tools/quest_npc_routes.json` separately marks source-reviewed relationships, while `tools/quest_flow_reviews.json` carries shared quest-flow notes with validated NPC, quest DB, and item DB source anchors; reviewed records identify Angelo#br for quests 9030/9031 and Kalipo#pa0829 plus the Hunting Dept. 2 Manager for quests 12106–12111. The exporter checks cited NPCs/cells and direct `setquest`/`erasequest` or the shared `que_dic` turn-in helper; reviewed `que_dic` rewards are cross-checked against the caller EXP value and helper completion/reward logic. Other references remain clues. When `db/quest_db.conf` is locally modified, the exporter intentionally reads tracked HEAD so user edits are not consumed. Active hunt counts remain sourced from server quest state. Hunt references link known monsters to the bestiary and supported maps to routes. NPC script-derived data does not cover conditional story/dialog steps, rewards, prerequisites, arbitrary runtime locations, or live SQL quest state. Versioned exports expand inherited Hercules `skill_tree.conf` records for 128 job IDs and `job_db2.txt` stat schedules for 147 IDs. Skill and prerequisite names resolve against renewal `skill_db.conf`; job→skill links show max levels and listed prerequisites, while jobs display cumulative stats and exact job-level bonus milestones. Status details join 540 icon rows to server status IDs, raw `sc_config` flags/recalculation flags, associated skills, explicit skill-db `StatusChange` links, and up to eight literal C call-site references per status (75 statuses/114 references total). These call sites aid source navigation but are not exhaustive status infliction or cure lists. Exact effects, duration/odds by level, complete sources, interactions, and cures remain explicitly undocumented. Conditional skill-script effects and IDs without a source row remain explicitly incomplete. Map and monster details offer route actions; item and quest entries cross-link to verified records. The existing searchable Bestiary can be opened through the unguarded Commands window and its Reveal all toggle is client-only; do not count it as the player policy. Navigate appears only when the graph has a verified location. Source revisions and incomplete-data labels remain visible.

When the window is opened from the in-game client, map details can also route to up to eight Towninfo facility coordinates via graph-verified paths. This is client-listed POI coverage only: script presence, service availability, exact cross-map reachability, and visual usability still require live acceptance.

## Acceptance

- Regenerate twice with identical bytes; `--check` catches a changed monster, item, skill, quest, and effective server rule.
- Existing DM views load after the export; IDs and drop links reconcile, with a report for records that do not.
- A new non-DM account searches “Hydra”, “Oridecon”, and a skill or effect term; traverses category links and can inspect verified rates, effects, and requirements before any encounter. Missing fields explain the coverage gap, not a hidden unlock.
- Two characters on one account share discovery badges/notes; another account does not. Reconnect restores the server snapshot without changing reference visibility.
- Compare a sample of displayed rates/formulas/refine odds with the live configured server before marking those fields complete.
